## 부록: 유형별 기록 가이드

### 버그
| 구분 | 개선 전 | 개선 후 |
|---|---|---|
| 테스트 | **재현 테스트가 실패**하는 출력 | 같은 테스트가 통과하는 출력 |
| 데이터 | 잘못된 값 (예: 이전 후 원래 랙 전력 `500W` 그대로) | 올바른 값 (예: `0W`) |

### 비효율
| 구분 | 개선 전 | 개선 후 |
|---|---|---|
| 측정 | 쿼리 수, 실행 시간, 조회 건수 | 같은 조건으로 재측정 |
| 결과 동일성 | 응답 값 | **응답 값이 같음**을 확인 |

측정 조건(데이터 건수, 호출 횟수, 반복 횟수)을 전/후 동일하게 적는다.

### 기능 추가
| 구분 | 개선 전 | 개선 후 |
|---|---|---|
| 동작 | 해당 요청의 현재 응답(누락·오류) | 명세대로의 응답 |
| 테스트 | 명세 시나리오 테스트가 실패 | 통과 |

### Code Smell (리팩토링)
| 구분 | 개선 전 | 개선 후 |
|---|---|---|
| 구조 | 클래스 줄 수, 메서드 수, 책임 개수, 하드코딩 위치 | 같은 지표 |
| 동작 | 안전망 테스트 통과 수 | **통과 수가 같거나 늘어남** |

리팩토링은 동작을 바꾸지 않는 것이 원칙이므로, 기존 테스트의 기대값을 수정하지 않았음을 반드시 확인한다.
